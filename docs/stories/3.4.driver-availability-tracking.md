# Story 3.4: Driver Availability Tracking

## Status: TODO (Critical Gap Identified)

## Problem Statement

The current driver-service implementation only tracks `isOnline` status. There is **no `isAvailable` tracking** to indicate whether a driver is currently serving a passenger.

### Current Behavior (Incorrect)
1. Driver goes ONLINE → Can update location, appears in search
2. Driver is assigned to Trip A → Still appears in search
3. Passenger B searches → Sees same driver (already on Trip A)
4. Driver could be "assigned" to Trip B → **Conflict!**

### Expected Behavior (Correct)
1. Driver goes ONLINE → `isOnline=true`, `isAvailable=true`
2. Driver is assigned to Trip A → `isAvailable=false`
3. Passenger B searches → Driver NOT in results (unavailable)
4. Trip A completes/cancels → `isAvailable=true`
5. Now driver appears in subsequent searches

## Acceptance Criteria

### AC 3.4.1: Track Driver Availability
**Given** a driver is ONLINE  
**When** they are assigned to a trip  
**Then** their availability status is set to `false`  
**And** they do NOT appear in nearby driver searches

### AC 3.4.2: Release Driver on Trip Complete
**Given** a driver has `isAvailable=false` (on a trip)  
**When** the trip status changes to `COMPLETED`  
**Then** their availability is set to `true`  
**And** they appear in subsequent nearby driver searches

### AC 3.4.3: Release Driver on Trip Cancel
**Given** a driver has `isAvailable=false` (on a trip)  
**When** the trip status changes to `CANCELLED`  
**Then** their availability is set to `true`  
**And** they appear in subsequent nearby driver searches

### AC 3.4.4: Search Filters by Availability
**Given** nearby driver search is performed  
**When** there are 5 online drivers, but 3 are on trips  
**Then** only 2 available drivers are returned  
**And** drivers on active trips are excluded

## Technical Implementation

### 1. Update Driver Status Schema (Redis)

```typescript
// Current (Incomplete)
interface DriverStatus {
  driverId: string;
  isOnline: boolean;
  timestamp: string;
}

// Required (Complete)
interface DriverStatus {
  driverId: string;
  isOnline: boolean;
  isAvailable: boolean;      // NEW: false when serving a trip
  currentTripId: string | null; // NEW: track assigned trip
  timestamp: string;
}
```

### 2. Update driver-service Endpoints

#### PUT /drivers/status
- Add optional `isAvailable` field
- Default to `true` when going ONLINE
- Default to `false` when going OFFLINE

#### PUT /drivers/availability (NEW)
```typescript
// Called by trip-service when driver is assigned/released
PUT /drivers/availability
{
  "isAvailable": boolean,
  "tripId": string | null  // For audit/debugging
}
```

### 3. Update searchNearbyDrivers

```typescript
// Current: Only checks isOnline
if (metadata.isOnline) {
  onlineDrivers.push(driver);
}

// Required: Check both isOnline AND isAvailable
if (metadata.isOnline && metadata.isAvailable !== false) {
  onlineDrivers.push(driver);
}
```

### 4. Redis Data Structure

```
# Driver status (updated)
driver:status:{driverId} = {
  "driverId": "uuid",
  "isOnline": true,
  "isAvailable": true,      // false when on trip
  "currentTripId": null,    // "trip-uuid" when assigned
  "timestamp": "2025-11-28T..."
}

# Available drivers set (NEW - for fast lookups)
driver:available = SET of driverIds  # Only drivers who can take trips
```

### 5. Event Flow for Trip Assignment

```
TripMatched event received by driver-service:
  1. Parse tripId and driverId
  2. Set isAvailable = false for driverId
  3. Set currentTripId = tripId
  4. Remove from driver:available set

TripCompleted/TripCancelled event received:
  1. Parse tripId and driverId
  2. Set isAvailable = true for driverId
  3. Set currentTripId = null
  4. Add back to driver:available set
```

**HIGH** - This is a critical business logic gap that allows:
1. Same driver assigned to multiple trips
2. Passengers seeing drivers who can't actually serve them
3. Poor user experience when driver is "matched" but can't come
